# UTF-8 — bytes, code points and visible characters

## Why lengths disagree
UTF-8 encodes Unicode scalar values with one to four bytes. Python len(str) counts code points, not bytes or user-perceived grapheme clusters. A displayed accented character may consist of one precomposed code point or multiple combining code points, so careless byte slicing can corrupt text.

## Executable demonstration (Python 3)
~~~python
import unicodedata

text = "Aé🚀"
encoded = text.encode("utf-8")
assert len(text) == 3
assert len(encoded) == 7
assert encoded.decode("utf-8") == text

combined = "e\u0301"
precomposed = "é"
assert len(combined) == 2
assert len(precomposed) == 1
assert unicodedata.normalize("NFC", combined) == precomposed
~~~
A uses one byte, é uses two and the rocket emoji uses four: 1+2+4=7. NFC normalization can make canonically equivalent sequences comparable; it is not a universal fix for visually confusable characters or locale-aware sorting.
