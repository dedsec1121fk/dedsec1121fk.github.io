# Κάθε εύρημα πρέπει να στηρίζεται σε αναπαραγώγιμα δεδομένα

## Ημερολόγιο αποδείξεων
Για κάθε συμπέρασμα κράτησε μοναδικό ID, hash πηγής, εργαλείο και έκδοση, offset/γραμμές που εξετάστηκαν, άμεση παρατήρηση, ερμηνεία και βαθμό βεβαιότητας. Το «υπάρχει import βιβλιοθήκης δικτύου» είναι παρατήρηση· το «η εφαρμογή στέλνει προσωπικά δεδομένα» είναι υπόθεση συμπεριφοράς που απαιτεί άλλο τεστ και κατάλληλη εξουσιοδότηση.

~~~text
E-001 | sha256=... | tool=readelf | section=.dynsym | observed=import name
H-001 | based-on=E-001 | interpretation=possible network feature
T-001 | approved test | result=not executed / observed ...
~~~

## Σύγκρινε ισοδύναμα builds
Όταν εξετάζεις δύο εκδόσεις, κράτησε hashes, αρχιτεκτονική και compiler settings. Σύγκρινε σταθερές δομές όπως symbols, strings, manifests ή schema. Διαφορετικά timestamps, debug data και optimizations μπορούν να αλλάξουν πολλά bytes χωρίς αλλαγή που βλέπει ο χρήστης. Δεν αποδίδουμε κάθε binary difference σε μία source αλλαγή.

## Ελεγχόμενο πείραμα
Άλλαξε ένα χαρακτηριστικό σε δικό σου πρόγραμμα και δημιούργησε εκδόσεις A/B με ίδιο toolchain. Κατάγραψε ποια γραμμή άλλαξε και τι προβλέπεις στο binary. Σύγκρινε strings και symbols, αναφέροντας και απρόσμενες διαφορές. Φτιάξε δύο builds χωρίς καμία αλλαγή κώδικα για να μετρήσεις πιθανή μη αναπαραγωγιμότητα.

## Υπεύθυνη παράδοση
Μία νόμιμη αναφορά ασφάλειας περιλαμβάνει περιορισμένα βήματα επανάληψης, επηρεαζόμενη έκδοση, προτεινόμενη διόρθωση και κανάλι επικοινωνίας. Αν λείπει απόδειξη αιτιότητας, σημείωσε «πιθανό» και εξήγησε ποια παρατήρηση λείπει.
