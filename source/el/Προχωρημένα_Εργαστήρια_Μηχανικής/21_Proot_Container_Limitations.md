# Το proot στο Termux δεν είναι κανονική εικονική μηχανή

## Σωστές προσδοκίες
Μια διανομή Linux μέσα σε proot επιτρέπει γνώριμα directories και package managers χωρίς root στη συσκευή. Δεν προσφέρει αυτομάτως προνομιακές λειτουργίες kernel, πραγματικό container isolation, ελεύθερα mounts ή πλήρες systemd ως PID 1. Εφαρμογή που λειτουργεί σε εγγενές Ubuntu μπορεί να αποτύχει επειδή το host παραμένει Android και οι δυνατότητες συστήματος είναι περιορισμένες.

~~~sh
uname -a
id
pwd
cat /proc/1/comm 2>/dev/null || true
command -v systemctl || true
~~~

## Διπλή διάγνωση
Όταν λείπει εκτελέσιμο έλεγξε αν βρίσκεσαι στο εγγενές Termux ή μέσα στη guest διανομή. Σύγκρινε `command -v python`, `uname -m`, το πρόγραμμα διαχείρισης πακέτων και το PATH πριν εγκαταστήσεις οτιδήποτε. Μήνυμα αποτυχίας για `/dev` μπορεί να οφείλεται στους περιορισμούς της πλατφόρμας και όχι στο ότι δεν χρησιμοποίησες sudo. Το `systemctl` μπορεί να υπάρχει ως αρχείο, χωρίς να τρέχει service manager.

## Απομόνωση χωρίς απώλειες
Κράτησε τον πηγαίο κώδικα σε version control και σημείωσε διανομή, αρχιτεκτονική και βασικές εξαρτήσεις. Μην κρατάς μοναδικά αντίγραφα σε προσωρινή guest περιοχή. Αν μία διαδικασία χρειάζεται πρόσβαση σε Android shared storage, έλεγξε πρώτα το υποστηριζόμενο path mapping αντί να υποθέσεις ότι όλες οι διαδρομές είναι ίδιες.

## Κριτήριο δοκιμής
Απόδειξε μία απλή εντολή χρήστη, μία αναζήτηση πακέτου και μία ανάγνωση αρχείου μέσα στο guest. Για αποτυχημένη υπηρεσία ή λειτουργία namespace κράτησε το ακριβές error ως περιορισμό πλατφόρμας. Δεν συνιστάται παραβίαση του Android sandbox για να μιμηθείς δυνατότητες πυρήνα.

## Κατάγραψε τρεις διαφορετικές ταυτότητες
Το UID που εμφανίζει ο guest, το host UID της Android εφαρμογής και τα kernel privileges της συσκευής δεν είναι το ίδιο πράγμα. Ένα prompt root στον guest περιγράφει το περιβάλλον που παρουσιάζεται στα user-space προγράμματα και δεν δίνει Android root. Αντίστοιχα, ο guest package manager εγκαθιστά guest πακέτα, ενώ το `pkg` στο native Termux χρησιμοποιεί διαφορετικό prefix και ABI περιβάλλον.

## Ίχνη για εκτελέσιμο που δεν ξεκινά
Σημείωσε `command -v python`, ενεργό shell και `uname -m` και στα δύο περιβάλλοντα. Missing loader, λάθος αρχιτεκτονική και απουσία εντολής είναι χωριστά σφάλματα. Κράτησε κάθε virtual environment μαζί με τον guest interpreter που το δημιούργησε. Μην αντιγράφεις τυχαία `.so` από το native Termux prefix στον guest για να εξαφανίσεις error.

## Όριο background εργασίας
Ξεκίνα αβλαβή σύντομη εντολή και κράτησε exit code. Σύγκρινε μεγαλύτερη εργασία όταν η Android εφαρμογή περάσει background. Ο guest δεν εγγυάται επιβίωση από τερματισμό host διεργασίας. Αποθήκευε πρόοδο σταδιακά και κάνε τη συνέχιση idempotent, ώστε η επανεκκίνηση να μη διπλασιάζει αποτελέσματα. Ένας guest service launcher μπορεί να εκκινεί daemon χωρίς να δημιουργεί πλήρες booted systemd.
