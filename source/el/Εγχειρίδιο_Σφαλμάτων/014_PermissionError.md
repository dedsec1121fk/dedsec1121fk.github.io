# Python PermissionError: ποια ακριβώς ενέργεια απορρίφθηκε;

Η PermissionError εμφανίζεται όταν το λειτουργικό αρνείται κάποια ενέργεια, όπως ανάγνωση αρχείου, δημιουργία εγγραφής σε προστατευμένο φάκελο ή εκκίνηση εκτελέσιμου. Δεν αποδεικνύει από μόνη της ότι πρέπει να αλλάξουμε όλα τα δικαιώματα ενός φακέλου. Πρέπει πρώτα να εντοπίσουμε την αποτυχημένη λειτουργία.

## Ασφαλές παράδειγμα σε προσωρινό κατάλογο

~~~python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    root = Path(folder)
    note = root / "note.txt"
    note.write_text("example", encoding="utf-8")
    assert note.read_text(encoding="utf-8") == "example"
    print("γονικός φάκελος:", note.parent)
~~~

Το επιτυχημένο παράδειγμα δείχνει ότι η διεργασία έχει πρόσβαση στον δικό της προσωρινό κατάλογο. Δεν σημαίνει ότι μπορεί να γράψει σε system configuration ή στον προσωπικό φάκελο άλλου χρήστη. Σύγκρινε τη διαδρομή, την ταυτότητα διεργασίας και την ενέργεια που αποτυγχάνει πριν επιλέξεις οποιαδήποτε διόρθωση.

## Ανάγνωση, εγγραφή, εκτέλεση και προσπέλαση

Ένα αρχείο μπορεί να διαβάζεται αλλά να μην επιτρέπει εγγραφή. Ένας φάκελος μπορεί να εμφανίζει περιεχόμενα αλλά να μην δέχεται νέα αρχεία. Σε POSIX τα γονικά directories απαιτούν δικαίωμα προσπέλασης. Επιπλέον, επιλογή mount noexec μπορεί να εμποδίζει εκτέλεση, ενώ η κοινόχρηστη αποθήκευση Android έχει ιδιαίτερους περιορισμούς για το Termux.

## Διαφορετικός έλεγχος σε κάθε λειτουργικό

Σε Linux/Termux χρησιμοποίησε id και ls -ld για το συγκεκριμένο αρχείο και τους γονικούς φακέλους. Σε Windows εξέτασε τις πραγματικές ACLs, το σημείο αποθήκευσης και πιθανές πολιτικές του συστήματος. Μη συγχέεις PermissionError με FileNotFoundError: το δεύτερο χρειάζεται εξέταση της διαδρομής, όχι τυχαία αλλαγή permissions.

## Στοχευμένη επίλυση

Για αρχεία που δημιουργεί η εφαρμογή προτίμησε κατάλληλο directory που ανήκει στον χρήστη. Αν απαιτείται πρόσβαση σε προστατευμένο σημείο, πρέπει να δοθεί μέσω νόμιμης, περιορισμένης διαχείρισης δικαιωμάτων. Απόφυγε chmod -R 777, καθολικό chown και ανεξέλεγκτη χρήση administrator/root. Επανάλαβε μόνο την αρχική λειτουργία και τεκμηρίωσε το αποτέλεσμα. Η πραγματική λύση διατηρεί τα δικαιώματα και την ιδιοκτησία σωστά.
