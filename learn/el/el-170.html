Κοινή μέθοδος εργαστηρίων χωρίς επαναλαμβανόμενο κείμενο

Τα επιμέρους workbooks παρουσιάζουν διαφορετικά syntax rules, invariants, αντιπαραδείγματα και προβλήματα ανά γλώσσα. Η παρακάτω μέθοδος ορίζεται μία φορά εδώ και δεν χρειάζεται αντιγραφή σε κάθε μάθημα.

  1. Περιβάλλον. Σημείωσε έκδοση compiler/interpreter, OS, backend και άδειες. Μία σύνταξη μπορεί να λειτουργεί σε συγκεκριμένη έκδοση, όχι σε όλες.
  2. Συγκεκριμένος ισχυρισμός. Όρισε ποια έκφραση, μετάβαση state, τύπο, απόδειξη, shape ή πράξη μνήμης εξετάζεις. Πρόβλεψε την έξοδο πριν τρέξεις.
  3. Δείγμα ελέγχου. Κράτησε ανέπαφο το starter. Κάνε πειράματα σε προσωρινό αρχείο με συνθετικά δεδομένα και τοπικά/test περιβάλλοντα.
  4. Δοκιμές δύο πλευρών. Κάλυψε έγκυρη περίπτωση, οριακή τιμή και σκόπιμα άκυρη είσοδο. Η απόρριψη πρέπει να έχει κατανοητή αιτία, όχι απενεργοποιημένο έλεγχο.
  5. Τεκμήρια. Φύλαξε source, εντολή ή ενέργεια host, πραγματική έξοδο, diagnostic και σύντομη εξήγηση. Το ότι μεταγλωττίζεται δεν αποδεικνύει σωστή εκτέλεση.
  6. Διαφορές πλατφορμών. Shaders, hardware simulation, proof checkers, τοπικά blockchain test chains και proprietary IDEs διαφέρουν από συνηθισμένο shell.
  7. Επέκταση μόνο μετά τον έλεγχο. Πρόσθεσε test πριν βελτιστοποιήσεις. Δες Unicode, numeric limits, empty inputs, resource lifetimes ή authorization όπου απαιτούνται.

Κάθε workbook έχει συγκεκριμένο τεχνικό στόχο. Τα γειτονικά Mastery Pathway, Practical Code και Technical Notes (εφόσον υπάρχουν) είναι συμπληρωματικά. Αν μια εκτέλεση δεν έχει ελεγχθεί στη συγκεκριμένη πλατφόρμα, δήλωσε ότι παραμένει μη επαληθευμένη· μην επινοείς αποτελέσματα.
