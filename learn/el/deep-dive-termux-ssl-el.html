Τι συμβαίνει

Η αποτυχία ελέγχου πιστοποιητικού μπορεί να οφείλεται σε λάθος ώρα Android, παλιό CA bundle ή παρεμβατικό proxy.

Πρακτικός έλεγχος

Έλεγξε domain και σφάλμα πιστοποιητικού πριν αλλάξεις ρυθμίσεις εμπιστοσύνης. Σύγκρινε με γνωστό αξιόπιστο δίκτυο.

Συνήθεις παγίδες

Ποτέ μην παρακάμπτεις μόνιμα SSL verification για να κρύψεις το σφάλμα. Ενημέρωσε έμπιστα πακέτα και έλεγξε το hostname.

Μικρό παράδειγμα για προσαρμογή

date && curl -Iv https://github.com

Στενή επιθεώρηση και ασφαλή diagnostic logs

Το curl -Iv μπορεί να εμφανίσει request headers και proxy λεπτομέρειες. Χρησιμοποίησε δημόσιο host χωρίς credentials και καθάρισε output πριν το μοιραστείς. Ξεκίνα με date -u και μικρό HEAD request με connect και total timeout. Λάθος ρολόι μπορεί να απορρίψει certificate dates ακόμη κι αν η αλυσίδα είναι σωστή.

Σύγκρινε hostname αιτήματος με certificate identity. Σύνδεση σε γυμνή IP δεν είναι ισοδύναμη αντικατάσταση: αλλάζει name validation και συνήθως TLS SNI. Αν απαιτείται εγκεκριμένος inspection proxy, ακολούθησε την τεκμηριωμένη εγκατάσταση trust, όχι αποδοχή άγνωστου πιστοποιητικού που εμφανίστηκε σε δημόσιο δίκτυο.

Στο Termux τα package CA αρχεία μπορεί να διαφέρουν από το Android/browser trust. Επιτυχία browser δεν αποδεικνύει ίδιο CLI store. Κράτησε app source, Android version, curl TLS backend και αν η αποτυχία προηγείται του HTTP. Ενημέρωση CA package δεν διορθώνει certificate για λάθος hostname.
