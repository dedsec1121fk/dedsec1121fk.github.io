Το όριο μπορεί να είναι λεπτά GitHub Actions, χώρος, δεδομένα Internet, μπαταρία ή χρόνος του αναγνώστη.

Πριν από ακριβό build:

  1. Δες ακριβώς ποια αρχεία άλλαξαν.
  2. Κάνε γρήγορους ελέγχους syntax.
  3. Δοκίμασε τοπικά τα σημεία που επηρεάστηκαν.
  4. Ομαδοποίησε συγγενικές αλλαγές.
  5. Τρέξε ακριβές integration test μόνο όταν χρειάζεται.
  6. Κράτα περιθώριο για διορθώσεις.

Παράδειγμα: μια βιβλιοθήκη Markdown δεν χρειάζεται Android emulator για να ενημερώσει την τεκμηρίωση. Αλλά δεν επιτρέπεται να πεις ότι «δοκιμάστηκε στο κινητό» αν έκανες μόνο syntax check.

Αν μια αλλαγή δίνει μικρή αξία και καταναλώνει πολύ budget, πιθανόν πρέπει να περιμένει.

Η σωστή οικονομία είναι να αφαιρείς άχρηστες εκτελέσεις, όχι να κρύβεις ότι δεν έγιναν αναγκαίοι έλεγχοι.
