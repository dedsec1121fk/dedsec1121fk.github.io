Κατανόηση του σημείου αποτυχίας στην Go

Μία μεταβλητή που δηλώνεται αλλά δεν χρησιμοποιείται απορρίπτεται συνήθως κατά τη μεταγλώττιση Go. Δεν αποτελεί το ίδιο πρόβλημα με ένα panic την ώρα εκτέλεσης. Οι ταυτόχρονες εγγραφές στον ίδιο απλό map χωρίς προστασία μπορούν να προκαλέσουν σφάλμα runtime, ενώ πρόσβαση εκτός ορίων σε slice προκαλεί panic. Η σωστή διάγνωση ξεκινά ξεχωρίζοντας μεταγλωττιστή, εκτέλεση και πρόβλημα συγχρονισμού.

package main
import "fmt"
func main() {
    values := []int{2, 4, 6}
    fmt.Println(values[2])
    // values[3] would panic: valid indices are 0, 1 and 2.
}

Η αναμενόμενη τιμή είναι 6. Πριν αλλάξεις τον δείκτη, σκέψου ότι το slice έχει μήκος τρία αλλά οι έγκυρες θέσεις είναι 0, 1 και 2. Για shared map, μπορείς να συγκεντρώνεις τις ενημερώσεις σε μία goroutine ή να προστατεύεις τις κρίσιμες λειτουργίες με sync.Mutex. Εφόσον υπάρχει συμβατό Go toolchain, δοκίμασε τον race detector σε μικρό απομονωμένο παράδειγμα. Μία επιτυχημένη εκτέλεση δεν αποδεικνύει ότι δεν υπάρχουν races.

Κριτήρια ελέγχου

Κατάγραψε έκδοση Go, ακριβή πηγαίο κώδικα και στάδιο στο οποίο εμφανίστηκε το σφάλμα. Σύγκρινε κενό slice, slice ενός στοιχείου και πρόσβαση εκτός ορίων. Αν δεν διαθέτεις compiler, κράτα χωριστές τις προβλέψεις από τις παρατηρήσεις και μην εμφανίζεις υποθετικά stack traces ως πραγματικά.
