## Apache_Spark_SQL — Αναλυτικός οδηγός εξάσκησης

### Ξεκίνησε από αληθινή σύνταξη
Το αρχικό παράδειγμα της Apache Spark SQL είναι η μικρότερη αφετηρία. Διάβασε τη σειρά των πράξεων και τον τρόπο εμφάνισης, έπειτα επιβεβαίωσέ το στο σωστό περιβάλλον. Μην θεωρείς ότι η σύνταξη άλλης γλώσσας έχει ίδια σημασία.

~~~text
SELECT concat('Hello, ', 'Ada', '!') AS greeting;
~~~

**Περιβάλλον εκτέλεσης:** Run the query with a Spark SQL session.. Έλεγξε έκδοση compiler/interpreter πριν τροποποιήσεις τον κώδικα και κράτησε την αρχική έξοδο. Δούλεψε σε προσωρινό κατάλογο, μακριά από πραγματικά δεδομένα.

### Οδηγούμενο εργαστήριο
Κάνε GROUP BY σε διπλά keys, εξέτασε EXPLAIN FORMATTED για exchanges/shuffles. Σύγκρινε aggregate που μειώνει γραμμές με window function που τις κρατά.

### Δοκιμές ορίων
Τα distributed plans Spark δεν είναι SQLite· data skew/partitions επηρεάζουν την απόδοση. Βάλε ORDER BY για σταθερή εμφάνιση.

### Προχωρημένη αποστολή
Φτιάξε ξεχωριστό αρχείο για το παραπάνω εργαστήριο και πειραματίσου με μία αλλαγή σε σειρά, σχήμα, τύπο, scope ή περιβάλλον, ανάλογα με τη Apache Spark SQL. Καθόρισε invariant και σύγκρινε αναμενόμενη με πραγματική έξοδο. Αν κάτι διαφέρει, απομόνωσε το ελάχιστο παράδειγμα πριν μεγαλώσεις το πρόγραμμα.

## Apache_Spark_SQL — Διαδρομή ουσιαστικής εξάσκησης

### Κατανεμημένο dataset
Η Spark SQL δουλεύει πάνω από διαμερισμένα datasets. Η εκτέλεση ενός SELECT δεν εγγυάται σειρά γραμμών αν δεν υπάρχει ORDER BY. Μία query που φαινομενικά εμφανίζει σταθερή σειρά σε μικρό δείγμα μπορεί να αλλάξει αποτέλεσμα εμφάνισης όταν μεταβληθεί ο αριθμός partitions.

~~~sql
SELECT customer_id, SUM(amount) AS total_amount
FROM purchases
WHERE amount IS NOT NULL
GROUP BY customer_id
ORDER BY total_amount DESC, customer_id ASC;
~~~

Η δεύτερη συνθήκη ταξινόμησης επιλύει τις ισοβαθμίες deterministically. Το SUM αγνοεί NULL στην είσοδο, αλλά ο σχεδιασμός για ελλείπουσα τιμή πρέπει να γίνει ρητά. Δοκίμασε τέσσερις εγγραφές για δύο πελάτες με ίσο άθροισμα, και πρόσθεσε NULL ποσό.

### Data shuffles και κόστος
Το GROUP BY συνήθως απαιτεί ανταλλαγή δεδομένων ανάμεσα σε partitions. Δεν γίνεται γρήγορο επειδή το SQL text είναι σύντομο. Χρησιμοποίησε explain plan για να ξεχωρίσεις local partial aggregation από shuffle/exchange. Σύγκρινε με query χωρίς GROUP BY και με κατάλληλη διαμόρφωση partitioning.

### Αποφυγή κακής υπόθεσης
Το LIMIT 10 χωρίς ORDER BY δεν σημαίνει «πρώτες δέκα χρονικά εγγραφές». Παρομοίως, ένα ORDER BY σε subquery δεν εγγυάται ότι ο εξωτερικός query consumer θα διατηρήσει την ίδια σειρά χωρίς δικό του ORDER BY. Γράψε ακριβή query output assertion πάνω στο τελικό ordered result.

### Τεστ και προέλευση
Δημιούργησε μικρό DataFrame με customer_id, amount και timestamp. Έλεγξε nulls, tie ordering και διαφορετικά partitions. Μετράς logical correctness ανεξάρτητα από performance. Κατάγραψε Spark/Java versions και explain output. Μη χαρακτηρίζεις τις δοκιμές εκτελεσμένες μόνο επειδή το query είναι τυπικά εύλογο.
