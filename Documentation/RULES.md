# Required maintenance rules / Υποχρεωτικοί κανόνες

These rules are binding editorial/engineering guidance for **human and AI maintainers**. They are not a license to operate on external systems.

## English — non-negotiable

1. **Privacy gate first:** Keep Developer's Mind anonymous. Do not import names, contact details, addresses, accounts, employers, finance, health, identifiable biography, raw chats, credentials or private repository contents. Treat even combinations of innocuous facts as identifying if they uniquely point to a person. Prefer generalized, transferable engineering methods.
2. **Structural boundary:** `DedSec-Project-Website/` contains the website. TikDev is `DedSec-Project-Website/TikDev.html`, not a second product directory. `Developer's Mind/` contains the anonymized provided archive. **Only one `Documentation/` folder exists at repository root.** Put translated docs under `Documentation/English/` and `Documentation/Greek/`, preserving topic subfolders.
3. **No duplicate content or templates:** Before adding a lesson, search both language indexes and archive paths for overlapping IDs, paths and equivalent body text. Do not make many thin pages by changing only the title. Include purpose, prerequisites, mechanism, real worked example, expected output, common failure modes, boundary tests, and maintenance guidance—tailored to the actual topic. Never add arbitrary filler to reach length.
4. **Relevance and accuracy:** Verify commands on the intended platform before declaring success. Preserve exact prerequisites; distinguish Termux/Android from desktop Linux and Windows. Do not invent executable commands or claim an unaudited tool is safe.
5. **Bilingual parity:** Every new standalone explanatory lesson has an English/Greek counterpart. Preserve code semantics while translating prose. Avoid two translated records with the same accidental search identity.
6. **Original source handling:** Original DedSec-authored material is governed by `LICENSE`. Keep component provenance accurate; do not invent ownership or permission claims.
7. **UI invariants:** Shared theme/language/search with no duplicates. Render all navbar icons as inline SVG/text in the HTML before JavaScript, with a measured readiness loader: centered DedSec logo, fixed galaxy and colorful progress. Do not add an artificial timer; wait for required local resources and prepared search, with an accessible failure escape. Show first-visit consent after readiness. Galaxy backgrounds have stars, planets and nebulae but no decorative oval orbital traces. Use sharp borders on actionable cards only. Launcher titles omit `.html` suffixes.
8. **TikDev behavior:** Isolate the TikDev toolbar under `.tikdev-toolbar` (never inherited `.app-header`), keep all five actions fully visible between the DedSec navbar and feed, and place the introduction immediately after the toolbar, without a giant empty region. Live GitHub discovery is online-only. Weekly cache refresh via the scheduled workflow validates configured music URLs and public repository metadata. A featured project occurs at the stated repository-card cadence and must not overwrite others' work.
9. **Stable URLs, assets and social metadata:** Verify all relative links after moving files. Every web HTML page has title, meaningful description, local project favicon, Open Graph/Twitter preview and a correct staging canonical URL. Keep root redirect functional. Use only original or permitted external images.
10. **Tests before claims:** Run static validation, unique-ID checks, browser viewport checks (dark/light, mobile/desktop, Greek/English), copy-button, expanding section, consent, navigation, search, TikDev feed and social preview tests. Link the **latest** successful GitHub Actions run. If it fails or is queued, report that precisely.
11. **Small CI footprint:** Use a single main branch; batch source edits and local checks before each GitHub push. Avoid repeating a full expensive workflow for cosmetic text changes. Preserve safe rollback commits.
12. **No unapproved deployment:** Test is the only edit target until explicit permission to migrate. No deletion of original Developer Mind repository or production website without separate approval.

## Ελληνικά — ίδιοι κανόνες

1. **Απόρρητο:** Κανένα προσωπικό αναγνωριστικό, επικοινωνία, τοποθεσία, βιογραφικό, οικονομικά, υγεία, ιδιωτικές συνομιλίες ή μυστικό στο Developer's Mind. Γενίκευσε τη μέθοδο εργασίας, όχι την ταυτότητα.
2. **Δομή:** Όλα τα αρχεία της ιστοσελίδας στο `DedSec-Project-Website/`. Το TikDev είναι **μία ενσωματωμένη σελίδα**. Υπάρχει **μόνο ένας** ριζικός φάκελος `Documentation/` με `English/` και `Greek/`.
3. **Περιεχόμενο:** Καμία διπλή εγγραφή, αντιγραφή πανομοιότυπου κειμένου ή γενικό καλούπι. Πρόσθεσε στόχο, προϋποθέσεις, μηχανισμό, διαφορετικό πρακτικό παράδειγμα, αναμενόμενη έξοδο, συχνά σφάλματα και ελέγχους ορίων.
4. **Ακρίβεια:** Επαλήθευσε εκτελέσιμες εντολές και ξεχώρισε Android/Termux, Linux και Windows. Μην παρουσιάζεις ανεξέλεγκτες δοκιμές ως επιτυχημένες.
5. **Μεταφράσεις:** Κάθε ουσιαστική νέα ενότητα έχει ισότιμη ελληνική και αγγλική εκδοχή. Ο κώδικας διατηρεί την ίδια συμπεριφορά.
6. **Δικαιώματα:** Το πρωτότυπο υλικό DedSec διέπεται από το `LICENSE`. Διατήρησε ακριβή την προέλευση των στοιχείων και μην επινοείς ισχυρισμούς ιδιοκτησίας ή αδειοδότησης.
7. **UI:** Μία πάνω μπάρα, καθαρή ανάγνωση, κεντραρισμένο λογότυπο DedSec πάνω από πολύχρωμη ένδειξη πραγματικής προόδου, σταθερός γαλαξίας, χωρίς τεχνητή χρονική καθυστέρηση, διέξοδος σε αποτυχία, Cookies μετά την ετοιμότητα, τετράγωνα εσωτερικά φωτεινά περιγράμματα, χωρίς επέκταση `.html` σε τίτλους εικονιδίων.
8. **TikDev:** Ανεξάρτητη μπάρα `.tikdev-toolbar`, με πέντε ολόκληρα ορατά κουμπιά και περιεχόμενο αμέσως από κάτω, χωρίς κενό ή αλληλεπικαλύψεις. Εβδομαδιαία ανανέωση δημόσιων metadata και έλεγχος συνδέσμων μουσικής με workflows. Διαφανής χειρισμός προβλημάτων δικτύου.
9. **Διαδρομές και SEO:** Έλεγξε σχετικά paths μετά τη μετακίνηση, favicon, OG preview, περιγραφή και canonical URL σε κάθε HTML.
10. **Έλεγχοι:** Python, Node, Chromium, κινητό/desktop, φωτεινό/σκοτεινό, ελληνικά/αγγλικά, search, copy, accordions, Cookies, TikDev και προεπισκοπήσεις. Αναφορά μόνο με αποδείξεις.
11. **Οικονομία Actions:** Λίγα συγκεντρωμένα commits, ασφαλές ιστορικό, δυνατότητα επαναφοράς.
12. **Μόνο Test:** Καμία αλλαγή παραγωγής ή διαγραφή αρχικών repositories χωρίς ρητή ξεχωριστή εντολή.

## 13. Mandatory documentation-sync rule / Υποχρεωτική ενημέρωση τεκμηρίωσης

**English:** Every change to website functionality, UI, routes, accessibility, scripts, CI, themes, content structure or deployment behavior MUST be accompanied **in the same commit** by updated, relevant documentation under **both** `Documentation/English/` and `Documentation/Greek/`. Update existing chapters instead of generating near-duplicate new ones. Explain what changed, why, which files own the behavior, expected behavior and edge cases, how to test it, and how to roll it back. Where a documented invariant changed, correct or explicitly supersede the old statement, including this Rules file if necessary. The `scripts/validate.py` Git-based check rejects commits that change functional files without both language updates. Generated metadata-only `[skip ci]` commits do not change the functional contract. Do not add empty or cosmetic documentation edits just to satisfy the check.

**Ελληνικά:** Κάθε ουσιαστική αλλαγή σε UI, λειτουργίες, routes, accessibility, scripts, CI, θέματα, δομή γνώσης ή deployment συνοδεύεται **στο ίδιο commit** από ενημερωμένη τεκμηρίωση **και** στους δύο φακέλους `Documentation/English/` και `Documentation/Greek/`. Διορθώνουμε τις παλιές οδηγίες αντί να προσθέτουμε σχεδόν ίδιες νέες. Γράφουμε ποια αρχεία άλλαξαν, γιατί, πώς δουλεύουν οι αλλαγές, οριακές περιπτώσεις, ελέγχους και rollback. Η επαλήθευση στο `scripts/validate.py` απορρίπτει λειτουργικές αλλαγές χωρίς ενημερωμένα έγγραφα και στις δύο γλώσσες. Δεν επιτρέπεται προσχηματική αλλαγή γραμμών απλώς για να περάσει ο έλεγχος.

## 14. Shared navigation and TikDev repository visibility / Κοινή πλοήγηση και ορατότητα TikDev

**English:** The Search, Moon/Sun, Language, and Account actions must share one icon system: the same inline SVG artwork and uniform labeled hit areas (78 x 50 px on desktop, 72 x 50 px on narrow mobiles) across the homepage, imported guides and TikDev. Avoid mixed text-symbol and font-dependent glyphs. Never replace the solid crescent with an unrecognizable thin arc. Preserve both themes and the original language action. Imported pages pre-render icons through `scripts/social_previews.py` and update theme artwork through `dedsec/Assets/merged-retro.js`.

The integrated TikDev page uses the uploaded upstream `TikDev-main.zip` as a reference for its working repository data card, README, save, owner/profile, stars, forks and open actions. Sharing was explicitly removed by the owner in the subsequent reader update; preserve the remaining interactions. Repo card text/actions must remain in normal document flow on mobile; never position `.repo-main` absolutely or cover it with an empty fullscreen introduction. Display a compact introduction and a visible real GitHub repository card within the feed; ensure users can scroll and use Start Exploring. When the GitHub API is inaccessible, show an honest fallback/error rather than empty space. Keep all 5 top toolbar buttons and all 3 bottom navigation tabs functional.

The three project trust indicators are larger but retain accurate provenance. The paragraphs directly beneath must describe **DedSec Project tools, scripts, installation, usage and maintenance**, not an overview of the separate programming-library website or TikDev. Changes require English/Greek documentation and browser checks in the same functional commit.

**Ελληνικά:** Τα τέσσερα κουμπιά Search, Moon/Sun, Language και Home έχουν ίδια γεωμετρία/inline SVG σε όλη την ιστοσελίδα· ποτέ ανάμεικτα Unicode σύμβολα με εικονίδια διαφορετικού μεγέθους. Το TikDev κρατά τα αυθεντικά λειτουργικά στοιχεία repository (README, αποθήκευση, δημιουργός, stars/forks, άνοιγμα· η κοινοποίηση αφαιρέθηκε με νεότερη ρητή εντολή) από το παρεχόμενο ZIP. Το περιεχόμενο των καρτών παραμένει σε φυσική ροή, όχι κρυμμένο με `position:absolute`, και η εισαγωγή δεν σκεπάζει τα έργα. Οι τρεις κάρτες αξιοπιστίας μεγαλώνουν και οι περιγραφές κάτω από αυτές αναφέρονται στο ίδιο το DedSec Project, όχι στη συνολική ιστοσελίδα. Υποχρεωτική τεκμηρίωση και στις δύο γλώσσες μαζί με ελέγχους.


## 15. No duplicate or near-duplicate knowledge / Απαγόρευση επανάληψης γνώσης

English: Before adding or expanding any lesson, search both language indices and Hacking Guide references for the same topic, intent and resolution. Do not add exact copies, superficial paraphrases, repeated boilerplate, synonym-reworded duplicates, identical error fixes, or placeholder/template pages. Enrich the existing canonical lesson with **new verifiable detail** rather than creating a second similar card. Use stable source IDs and paths, maintain provenance to the owner's Hacking-Guide-Project, and preserve authorized-only security examples. Update the English AND Greek canonical article and maintenance documentation together. An automated normalized-title/paragraph overlap test must reject identical or highly similar *new* records; a reviewer checks semantic overlap.

Ελληνικά: Πριν από νέο μάθημα, ελέγχουμε και τις δύο γλώσσες και την αρχική πηγή Hacking Guide για την ίδια έννοια ή λύση. Δεν προσθέτουμε ίδια κείμενα, κοντινές παραφράσεις, επαναλαμβανόμενα templates, παρόμοιους τίτλους/βήματα ή σελίδες χωρίς ουσία. Επεκτείνουμε το μοναδικό υπάρχον μάθημα με νέο και ελεγμένο περιεχόμενο. Κρατάμε μοναδικά ID/paths, αναφορά στην πηγή και μόνο εξουσιοδοτημένα παραδείγματα ασφάλειας. Κάθε αλλαγή ενημερώνεται σε Αγγλικά και Ελληνικά και ελέγχεται για νοηματική ομοιότητα.


## 16. Depth, unique lessons and canonical source parity / Ουσία, μοναδικότητα και αρχικά αρχεία

**English:** Every future knowledge-base update must revise the existing canonical Markdown lesson **and** its deployed static JS record, with the **same stable ID**, bilingual scope and meaningful topic-specific differences. No copied paragraphs, cosmetic paraphrases, empty workbooks, duplicated tutorials, repeated boilerplate, generic titles or generated filler. Before committing, inspect semantic overlap across each locale, official references, and the full Hacking Guide source. New sections need accurate mechanisms, runnable or observable exercises, failure cases, platform/permission boundaries, a verification step and precise links to original manuals where appropriate. Keep authored citations/provenance. The source files live in `Developer's Mind/Keep Programming Alive/{English,Greek}/`; data files are deployable snapshots. A validator now checks 68 enriched canonical Markdown articles plus 16 Termux files for exact source parity. The original `Hacking-Guide-Project` holds its own master chapters; their source identity and 140-per-language ordering remain intact in the offline reference, not 280 newly rewritten "near duplicate" posts.

**Ελληνικά:** Κάθε νέα συντήρηση αλλάζει το ήδη υπάρχον αυθεντικό Markdown **και** το αντίστοιχο στατικό JS, με το ίδιο μοναδικό ID και πραγματική τεχνική ουσία και στις δύο γλώσσες. Απαγορεύονται αντίγραφα, κοντινές παραφράσεις, κενά workbooks, επαναλαμβανόμενα templates, γενικοί τίτλοι και κείμενα χωρίς πραγματική πληροφορία. Ελέγχουμε νοηματική επικάλυψη με το υπάρχον υλικό, τις επίσημες πηγές και το αρχικό Hacking Guide. Κάθε επέκταση χρειάζεται συγκεκριμένη εξήγηση, ελέγξιμη άσκηση, οριακές περιπτώσεις, περιορισμούς πλατφόρμας/αδειών και κριτήριο επιτυχίας. Ο validator ελέγχει 68 ενημερωμένα άρθρα και 16 πρωτότυπα Termux αρχεία. Τα 140 κεφάλαια ανά γλώσσα Hacking Guide διατηρούν αναφορά στο αρχικό repository, όχι διπλό περιεχόμενο με άλλο όνομα.


## 18. Canonical in-place lesson enrichment / Επέκταση μοναδικών μαθημάτων

English: The expanded source material under data/lesson-expansions-*.js is keyed by exact language + existing archive path. A lightweight first-paint loader appends it to the ORIGINAL record, without adding a second search item, new ID or duplicate card. The mirrored Markdown under Developer's Mind/Keep Programming Alive/{English,Greek} must include the identical extension. scripts/export_developer_mind.py reproduces the mirror; scripts/audit_knowledge.py rejects duplicate targets, missing originals, empty filler or unmatched locale counts. Each example must include a reproducible observation, limitations and a topic-specific exercise. Do not mass-produce repeated templates or claim that every original language entry is now comprehensive.

Ελληνικά: Το data/lesson-expansions-*.js επεκτείνει το ήδη υπάρχον μάθημα με κλειδί γλώσσα + αρχικό path, χωρίς δεύτερο αποτέλεσμα αναζήτησης ή νέο ID. Τα Markdown στον Developer's Mind/Keep Programming Alive/{English,Greek} διατηρούν το ίδιο πρόσθετο περιεχόμενο. Ο exporter συγχρονίζει τα αρχεία και ο έλεγχος απορρίπτει διπλούς στόχους, ελλείψεις, πρόχειρη γενική ύλη και άνισες γλώσσες. Κάθε ενότητα περιέχει πραγματική άσκηση, περιορισμούς και ελέγξιμο αποτέλεσμα. Δεν δηλώνουμε ότι όλα τα πρωτότυπα μικρά άρθρα ολοκληρώθηκαν.


## Website search and publication gates / Αναζήτηση και δημοσίευση

English: The shared top-navbar search indexes the entire local website, including imported page bodies and the effective learning catalogue. TikDev keeps its explicitly separate GitHub repository search. Generate data/site-search.js from canonical source pages; never add alias/pre-render mirrors as duplicate hits. The startup percentage tracks weighted readiness work, not downloaded bytes. Normal first-tab startup displays only the logo and bar; keep status text screen-reader accessible and show recovery text only on failure. Subsequent same-tab navigation runs readiness in the background without repeated full-screen gates. Scan public root aliases, CSS imports, JS, sitemap, robots, canonical/hreflang, llms.txt and full bilingual llms-full.txt content for each build profile. No claim of publication readiness may hide failed browser checks or untested hardware. Test-only writes remain mandatory until the owner explicitly authorizes production.

Ελληνικά: Η κοινή αναζήτηση επάνω καλύπτει όλη την τοπική ιστοσελίδα και τον ενεργό κατάλογο γνώσεων. Το TikDev διατηρεί χωριστή αναζήτηση αποθετηρίων GitHub. Το data/site-search.js παράγεται από κανονικές πηγές, χωρίς διπλά αποτελέσματα από αντίγραφα URL ή προεπισκοπήσεις. Το ποσοστό μετρά σταθμισμένη ετοιμότητα, όχι ληφθέντα bytes. Η πρώτη φόρτωση καρτέλας δείχνει μόνο λογότυπο/μπάρα· το κείμενο κατάστασης παραμένει προσβάσιμο σε screen readers και εμφανίζεται μόνο σε αποτυχία. Η επόμενη πλοήγηση στην ίδια καρτέλα ελέγχεται στο παρασκήνιο χωρίς νέο fullscreen loader. Ελέγχονται δημόσια αντίγραφα, CSS, JS, sitemap, robots, canonical/hreflang, llms.txt και πλήρες δίγλωσσο περιεχόμενο llms-full.txt ανά προφίλ. Η αναφορά ετοιμότητας δεν αποκρύπτει αποτυχημένες δοκιμές ή μη ελεγμένο υλικό. Αλλαγές μόνο στο Test ώσπου να εγκριθεί ρητά η παραγωγή.
