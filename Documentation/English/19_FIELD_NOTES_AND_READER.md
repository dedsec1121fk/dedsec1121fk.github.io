# Website search, startup and reader maintenance

The site has 1,776 effective knowledge records, 888 per language. The shared search now also includes 184 canonical website-page records. `scripts/build_site_search.py` extracts page bodies and translated attributes from the source HTML, excluding navigation, footer, executable scripts and styles. Physical public URL aliases and generated lesson previews are not extra results. `data/site-search.js` is generated and CI rejects stale content with `--check`.

`assets/knowledge-search.js` owns parsing and ranking. `assets/ui.js` combines website pages with the effective learning catalogue and incrementally normalizes the index in small yielding batches. Queries support phrases, literal exclusions, OR, language, topic, type and title filters. `type:page` opens real page URLs; code/lesson hits retain stable lesson IDs. `topic:website` restricts page hits. Root search stays local; TikDev's bottom search remains an explicitly separate GitHub repository operation. The shared navbar search from imported pages and TikDev opens `index.html?search=1#library`. A supplied `?q=...` can initialize a local query without storing it.

`assets/boot.js` runs before theme CSS. Published startup waits for the basic DedSec pages (installation, tools, Assistance landing page, FAQ, privacy, contact and founder story in both languages), their presentation dependencies, current-page images, galaxy backgrounds, active fonts and first paint. It does not fetch lesson previews, raw sources, crawler files or knowledge databases. There is no artificial minimum duration. Retry/Continue remain available after a genuine load failure.

The root HTML declares knowledge scripts as inert `data-knowledge-src` entries. Opening a topic/lesson or using search loads them sequentially, applies bilingual enrichments once and builds the local search index in yielding batches. The homepage and the library's folder chooser do not download or index knowledge. An inline bilingual loading/retry message handles that first explicit use; navigation remains available. Search still covers the whole website after its data is ready.

`scripts/startup_manifest.py` follows local presentation dependencies from the basic page allowlist, including CSS imports and fonts, and hashes only that small startup bundle. Knowledge, source downloads and article pages are excluded. The builder fingerprints both normal script URLs and inert knowledge URLs. `offline-worker.js` verifies SHA-256, reuses unchanged basic files and activates a cache only after the basic bundle succeeds. Old full-site caches are removed after the new bundle activates. Basic pages can reopen offline; knowledge needs its requested files or a locally served complete download. No background full-archive warmup is scheduled. Published cache behavior requires HTTPS or localhost. Raw source previews use ordinary page readiness.

Search extraction preserves paragraph boundaries and inline text spacing. Results show complete relevant paragraphs, or complete matching sentences for unusually large blocks. The shared passage helper lives at the start of `page-controls.js`; it preserves inline identifiers and fenced code. Page links carry public excerpt text in the `#find` fragment, an optional fallback `term`, and `contentlang` to prevent the saved UI language redirecting a result to the wrong translation. Lesson links use `#read:ID;find=...&term=...`. The original query is not attached to destination URLs. Destination highlighting maps normalized Greek accents/whitespace back to DOM text ranges, opens enclosing details/FAQ answers, scrolls below the fixed navbar, and uses safe text nodes rather than HTML injection. Copy still reads the unchanged code text.

`assets/page-controls.js` owns Copy and Back. Copy preserves code text and has Clipboard API fallback plus honest failure feedback; it never executes commands. Fenced, indented and recognized inline commands receive controls without duplicating installation-guide buttons. Root navigation maintains its own small route stack; direct links have a safe library/home fallback. Back is at the upper right on non-home pages, imported guides, TikDev and static articles. Both themes and languages remain supported. Share/Preview and the Main Website footer button stay removed; article URLs remain valid.

`assets/galaxy.css` and `assets/refinement.css` keep the wallpaper in a stationary composited layer, avoiding fixed-body wallpaper repaints during scrolling. Loader progress mutations do not trigger full Copy/Back rescans. Home launchers wrap at six desktop or three narrow-mobile columns and center incomplete rows. The first badge displays the owner-requested “#1 In Google Results” wording. GitHub counts retain dated snapshot provenance when optional live updates are not allowed.

The browser workflow checks mobile/desktop themes and languages, all imported pages, exact clipboard behavior, search body hits, Back geometry, short rows and loader behavior under deliberately blocked or failed resources. Roll back the complete commit—including paired documentation and generated index—if a release must be reverted; do not mix individual old/new modules. `build_portable_site.py` fingerprints local JS/CSS URLs to make the release transition cache-safe.

## One startup overlay per tab and website scope

After the first fully successful startup, `boot.js` records `dedsec:boot-ready:` plus the asset scope and boot-script fingerprint in sessionStorage. Later document navigation, language changes and reloads in that tab run readiness/cache updates in the background, without mounting the full-screen overlay or hiding content. A new tab or boot-script fingerprint gets a fresh startup check. The account Worker and static site are different origins, so each has its own tab-session marker; no credentials or private notes are stored in it. If sessionStorage is unavailable, readiness remains safe but the once-per-tab optimization is unavailable.

Normal startup shows only the fixed galaxy, centered logo and colorful progress bar. Percentage text is hidden; status announcements remain visually hidden for assistive technology. A genuine failure still reveals the localized failure message and Retry/Continue/help controls, and never records success. Failed loads cannot silence the next attempt. Do not skip resource/font/image checks to remove repeated splashes: preserve the readiness state machine and basic-only cache scope. The browser regression stalls a later page stylesheet and verifies no second overlay, then checks reload, first-load progress, hidden normal text and accessible failures.
