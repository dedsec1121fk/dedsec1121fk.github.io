# Windows 95 inspired Galaxy — design and knowledge maintenance

## Core visual requirements
The Test staging site uses crisp 1990s desktop geometry: **square corners everywhere**, thin borders, modest controls, and a readable local font stack `"MS Sans Serif", Tahoma, "Microsoft Sans Serif", Arial, sans-serif`. The actual Microsoft Sans Serif bitmap font cannot be assumed to be installed on Android, so Tahoma/Arial is a deliberate local fallback; no third-party font download is needed. Do not replace Icon Font Awesome pseudo-elements' fonts or the icons will become blank.

The two themes use a common white/black foreground system: dark text `#fff`, light text `#111`. Both the root and imported navbar glyphs—including the EN/ΕΛ switch—must match that foreground. Dark mode has a **0.64-opacity black reading veil** over a deep-space palette. Light mode is a bright pearl/lavender sky with a subtle 0.18-opacity white veil. The fixed header remains opaque so text behind it does not ghost through on scroll; article sections and archive cards are transparent. Inputs and code areas retain extra contrast.

Source files: `assets/galaxy.css` (shared palette, overlay and square corners), `assets/ui.css` (root Windows 95 layout and simple icon tiles), `dedsec/Assets/merged-retro.css` (high-specificity legacy override). The launcher glyphs are in `SIMPLE_GLYPHS` in `assets/ui.js`: 22 distinct outlines, one color, simple shapes and no glossy frames. The DedSec project logo remains a brand asset; **no butterfly decorations** are present in either space scene.

## SVG asset structure
`assets/starfield-dark.svg` and `assets/starfield-light.svg` are independent local 890×650 static scenes. Each scene contains hundreds of stars, small glow halos, **three distinct spiral-galaxy clusters**, an irregular nebula field, and **seven planets** with a mix of ringed, cratered and striped variants. The file uses SVG `radialGradient` elements with identifiers `glow`, `nebula`, `galaxy-core`, `galaxy-haze`, `planetA` through `planetE`. The SVG is generated as a deterministic static asset, not a continuously animating canvas, to protect low-end Android scrolling. For human editing, change the source SVG objects and gradients directly; do not use image compression that blurs the stars. For AI editing, preserve IDs and scene dimensions and do not reintroduce butterfly, alien or dog decorations.

## Knowledge audit and content improvements
All searchable knowledge resides in `data/en.js` (1,188 EN), `data/el.js` (1,188 EL), and `data/methods.js` (30 bilingual reasoning entries). The separate Developer Mind source archive remains independent. **24 English practical Python-lab reading pages** were expanded from one-line placeholders to distinct explanations of aims, boundaries, tests and source-file references. Two cross-dialect SQL samples in both languages now clearly identify their engine-specific context instead of appearing interchangeable.

`scripts/audit_knowledge.py` inspects every document row and every body line, checks nonempty content, unique IDs/paths, locale, parity and duplicate normalized full bodies, and emits `Documentation/KNOWLEDGE_AUDIT.json` at build time. Repeated legitimate titles (for example, a glossary definition and a worked algorithm) are counted but not deleted. The reader's `displayTitle()` disambiguates same-name entries; `bodyWithoutRepeatedTitle()` hides redundant first Markdown headings without changing original source material. Similar code examples in EN/EL, or identical generic syntax across language ecosystems, should be investigated before deletion. The audit does **not** prove semantic correctness of every script, and a line-by-line *automated* inspection is not equivalent to a manual expert review of all 2,406 records.

## Release and human / AI checklist
Run `python3 scripts/audit_knowledge.py`, `python3 scripts/validate.py`, `node --check assets/ui.js`, and the headless Chromium test `node scripts/browser_audit.mjs` in the published workflow. In the Chromium report, examine mobile/dark, mobile/light, desktop, Greek installation, Knowledge category, and full lesson views. Confirm text/icon contrast (white versus black), no corner rounding, no horizontally clipped content, centered knowledge headings and descriptions, and distinguishable dense-space imagery. Keep original text/source untouched unless the changes are specifically documented, avoid repeated filler, and never silently edit production.

If any browser assertion fails, inspect `browser-screenshots/audit.json` and the workflow images, correct the winning CSS selector or incomplete JS, and commit all corrections together to conserve GitHub Actions minutes.
