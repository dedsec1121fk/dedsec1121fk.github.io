# Routine maintenance by a person

Work from the repository root. Record `git rev-parse HEAD` and `git remote -v`; stop if the write target is not Test. Preserve history and group related edits into one reviewed commit. Do not force an upstream reimport: `scripts/import_dedsec.py` is a historical import helper, not the everyday build.

Find the responsible module in [the system map](09_COMPLETE_MAINTENANCE.md). Root launcher text/routes belong to `DedSec-Project-Website/assets/ui.js`; imported EN/EL article text belongs to the corresponding `dedsec/Pages/` and `dedsec/el/Pages/` files. Shared imported compatibility behavior is in `dedsec/Assets/merged-retro.js`. Search passages are generated from article text; do not manually patch `data/site-search.js` as the source of truth.

For a wording or content change, edit both languages, preserve stable lesson IDs and source paths, and search for equivalent existing content before adding anything. Read `scripts/knowledge_catalogue.py` to see effective records and overlays. Check the authored markdown and any applying data overlay together; changing an unused original does not change the effective lesson. Keep actionable code exact and translate surrounding explanation. Run content/search checks before regeneration and build.

For styles, inspect the computed winning selector in each affected page family. Change the owning rule instead of appending competing overrides. Check light/dark, Greek/English, mobile 320/390px and desktop 1280px, keyboard focus, contrast, reduced motion, open details, code copying and long names. Navigation actions remain Search, Theme, Language, Account; Back appears upper-right within non-home content. Short final icon rows are centered. Trust and content panels retain the requested transparency.

For accounts, inspect server, pure client core, rendered form, privacy text and migration together. Never rely on client limits or disabled buttons for authorization. New SQL changes use a new migration, never rewrite an applied migration. Keep user exports and backups private. Run SQLite and API tests, including malformed requests and concurrent-write conflicts. After release, perform a real owner-driven Turnstile registration, sign-out/sign-in and TXT export; mock tests cannot replace that.

Regenerate search, run the [release checklist](03_BUILD_AND_RELEASE.md), review `git diff --stat` and `git diff --check`, and update relevant English/Greek documentation in the same commit. Inspect the exact commit's Actions result and live Test page. On failure, read the failing step before another push. For rollback, revert the source commit and rebuild; database changes need their own compatible recovery plan. Keep production and backup untouched.
