# Publication audit and acceptance scope

This batch modifies Test only. Its offline publication gate builds **main, Test and backup profiles locally**, then scans each complete output. Production and backup repositories are not updated by these checks. Test intentionally remains noindex and has no production CNAME. Do not treat its crawler policy as the public profile's policy.

The scan covers 2,135 HTML pages per profile, 1,955 sitemap URLs, canonical and language-alternate targets, local HTML and CSS references, favicons, static Open Graph/Twitter metadata, 23 website-owned JavaScript files and four unique inline executable scripts. It verifies 8,896 fingerprinted JS/CSS references against the bytes actually shipped. Alias copies are intentional deployment mirrors; they are not extra search/knowledge records. The 404 canonical is deliberately omitted from the sitemap.

`llms.txt` is a concise entry guide. `llms-full.txt` contains all 180 page records and all 1,776 effective learning records, with a source URL for each: 1,956 content records. The audit rejects foreign deployment origins, missing source targets, omitted or duplicate lessons, missing sitemap targets and stale module fingerprints. It also checks robots/CNAME policy for the chosen profile. Prose cross-references in the full text resolve to absolute deployment URLs; fenced and inline examples retain literal sample links. Full LLM text is generated from the current canonical sources; it is not a second hand-maintained content database.

The broader scan found and repaired two existing defects: CSS copied to public-root aliases still imported styles at the old directory depth; and the old full LLM file was only a lesson-link index. Shared controls also resolve dynamically inserted consent and refinement assets from their actual source or public-alias directory depth. A real-browser alias check rejects missing runtime resources. It also adds missing article favicons, fingerprinted local resources and restores the owner-requested Google-results badge. These changes are covered by build/audit checks rather than an appearance-only screenshot review.

Knowledge review deepens 24 existing paired topics, 48 guides, without adding duplicate lesson IDs. `DETAIL_REVIEW_INVENTORY.json` lists reviewed sources, hashes and executable examples. The complete catalogue remains 888 records per language. Exact-body/paragraph checks, 0.72 near-duplicate screening, source/index parity, fence validation, translated topic pairing and local reference checks run across the relevant full catalogues. Thirty-five Python unit tests and the existing renderer/search fixtures accompany the new audit. The 22 new runnable examples comprise 18 Python programs and one each in JavaScript, Bash, C and C++; Rust/TypeScript additions require their toolchains for execution evidence. Earlier reviewed examples remain in the regression suite.

The startup manifest covers only basic DedSec pages and their presentation dependencies with exact SHA-256 hashes. Tests reject knowledge/data/raw paths, verify that homepage readiness makes no knowledge database requests, delay a basic page before releasing the loader, reopen a basic page offline, and check on-demand search passages and highlights. The entire generated website is still audited for links, SEO and LLM coverage.

Reproduce the offline scan with `python3 scripts/build_site_search.py --check`, the catalogue audits and unit tests in `.github/workflows/static.yml`, then `python3 scripts/build_portable_site.py --target test --output .site-publish` and `python3 scripts/audit_publication.py --output .site-publish`. Repeat the build/audit with main and backup targets in separate output directories. Use `PUBLICATION_AUDIT.json` for the recorded local results.

A passing gate means there are no detected blockers in this static publication scope. It is not an independent certification of every technical statement, every remote service or every real device. Live GitHub discovery/music depend on external services; browser CI uses controlled fixtures for repeatability. Android/Windows hardware and unavailable language runtimes remain outside the local execution claim. The owner must separately authorize promotion to production.
