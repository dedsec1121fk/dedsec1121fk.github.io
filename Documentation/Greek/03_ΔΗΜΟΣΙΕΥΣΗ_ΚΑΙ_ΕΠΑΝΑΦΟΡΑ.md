# Build, έλεγχος και δημοσίευση Test

Εκτέλεσε από τη ρίζα με Python 3.10+ και Node 24 (`node:sqlite` για τα account tests). Χρησιμοποίησε απομονωμένο Python περιβάλλον με `mistune==3.2.0`· το κανονικό build δεν χρειάζεται BeautifulSoup ή cryptography συσκευασίας scripts. Οι εντολές είναι για Linux shell. Σε Windows χρησιμοποίησε `py -3`/`python` και `.venv\Scripts\python.exe`· σε Termux τα αντίστοιχα πακέτα Python/Node. Η πραγματική απόδοση Android χρειάζεται έλεγχο συσκευής.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install mistune==3.2.0
python3 scripts/build_site_search.py
python3 scripts/build_site_search.py --check
python3 scripts/validate.py
python3 scripts/audit_knowledge.py
python3 scripts/audit_knowledge_depth.py --strict
python3 scripts/audit_offline_links.py
python3 scripts/audit_near_duplicates.py
python3 scripts/audit_complete_catalogue.py
python3 -m unittest discover -s scripts -p 'test_*.py'
node scripts/test_account_core.cjs
node scripts/test_account_service.mjs
node scripts/test_knowledge_renderer.mjs
node scripts/test_knowledge_search.mjs
node scripts/test_search_passages.mjs
node scripts/test_save_links.cjs
node scripts/test_offline_worker.mjs
python3 scripts/verify_reviewed_examples.py
.venv/bin/python scripts/build_portable_site.py --target test --output .site-publish
python3 scripts/test_portable_site.py --output .site-publish
python3 scripts/audit_publication.py --output .site-publish --report publication-audit.json
```

Η παραγόμενη αναζήτηση γίνεται commit μαζί με τις πηγές. Build output, περιβάλλοντα και τοπικές αναφορές δεν αποτελούν αρχικό κώδικα και μένουν έξω από το commit. Για προεπισκόπηση τρέξε `python3 -m http.server 8765 --directory .site-publish` και άνοιξε `http://127.0.0.1:8765/`. Χρησιμοποίησε HTTP αντί `file://`, επειδή διαφέρουν fetch, workers και modules.

Για το ακριβές browser harness σέρβιρε αντίθετα τη **ρίζα repository** (ίδια θύρα, ξεχωριστή συνεδρία server), κράτησε το `.site-publish`, εγκατάστησε `playwright-core@1.58.2` στο `/tmp/dedsec-browser` και δώσε Chromium μέσω `CHROME_PATH` αν δεν βρίσκεται σε τυπική διαδρομή του script. Τρέξε `node scripts/browser_audit.mjs`. Η απόλυτη προσωρινή διαδρομή dependency αποτελεί σήμερα μέρος του harness. Σε Windows χρησιμοποίησε WSL ή CI· μην δηλώνεις εκτέλεσή του επειδή πέρασαν στατικοί έλεγχοι. Εξέτασε `browser-screenshots/` και audit. Τα account mocks δεν στέλνουν πραγματικά email ούτε παρακάμπτουν CAPTCHA.

Το `.github/workflows/static.yml` εκτελεί ελέγχους, εγκαθιστά Markdown/browser dependencies, χτίζει με `--target auto`, ανεβάζει αποδεικτικά και δημοσιεύει Pages μόνο όταν `github.repository == 'dedsec1121fk/Test'` και περάσουν τα προηγούμενα βήματα. Δεν αντιγράφει upstream πηγές ούτε κάνει commit generated αλλαγών. Άγνωστο αυτόματο profile απορρίπτεται. Τα άλλα build profiles προορίζονται για ξεχωριστά εξουσιοδοτημένα releases.

Κάνε ένα συγκεντρωμένο commit μετά τους τοπικούς ελέγχους, διατήρησε το parent SHA και εξέτασε το συγκεκριμένο push run. Αποτυχία browser εμποδίζει τη δημοσίευση. Έλεγξε `deployment-manifest.json`, Test noindex/robots, τις δύο γλώσσες account, σχετικά assets, προορισμούς αναζήτησης, loader, θέματα και footer μετά το deployment. Το workflow **δεν** εγκαθιστά το `account-service/worker.mjs`· ακολούθησε χωριστά τον οδηγό ιδιωτικών λογαριασμών. Πραγματική εγγραφή, ιδιοκτησία email και δικαίωμα ανταμοιβών χρειάζονται ζωντανούς ελέγχους πέρα από fixtures.

Για επαναφορά δημόσιας συμπεριφοράς χρησιμοποίησε κανονικό revert commit και νέο build. Κράτα προηγούμενη Worker έκδοση με αντίστοιχο catalogue/secrets. Πριν από migration κράτα ιδιωτικό backup D1. Μην εκτελείς τυφλά παλιό Worker με positional SQL inserts σε νεότερο schema· δες την προειδοποίηση συμβατότητας στο κεφάλαιο 21.
