# Επέκταση γνώσης DedSec Project — επιμέλεια και συντήρηση

## Τι προστέθηκε στο πακέτο

Η νέα έκδοση περιλαμβάνει **35 ζευγάρια εξειδικευμένων μαθημάτων** στα Αγγλικά και στα Ελληνικά (70 νέα Markdown guides), με συγκεκριμένες εντολές ή δείγματα κώδικα, αναμενόμενα αποτελέσματα, ακραίες περιπτώσεις και όρια επαλήθευσης. Παραμένουν ο προηγούμενος κατάλογος, η χωριστή βάση troubleshooting Termux, ο αρχικός Hacking Guide και οι τρεις δυνατότητες ανάπτυξης της ιστοσελίδας. Επιπλέον διορθώθηκαν **44 τίτλοι ανά γλώσσα** που ξεκινούσαν μηχανικά με «Topics:» ή «Θέματα:». Οι νέοι τίτλοι αναφέρουν τι πραγματικά περιέχει το αντίστοιχο μάθημα, χωρίς αλλαγή IDs ή απώλεια κώδικα.

Το νέο υλικό καλύπτει αποθετήρια Termux, Android storage, περιορισμούς background, native Python packages και proot· δικαιώματα Linux, inodes, services, DNS/TLS και SSH· Python/PowerShell στα Windows, εγκατάσταση APK, Git recovery και οικονομική χρήση CI· εξουσιοδοτημένη ανάλυση ELF, PE, .NET, JS bundles, PCAP, APK και ZIP· secrets, άδειες και SBOM· εργαστήρια Python, JavaScript, Bash, Rust, C και SQLite.

## Ορθότητα, επίσημες πηγές και άδεια έρευνας

Τα παραδείγματα δεν παρουσιάζονται αυτομάτως ως εκτελεσμένα σε κινητό ή ειδικό compiler. Οι εκδόσεις εργαλείων επηρεάζουν εντολές και συμπεριφορά. Έλεγχε πρώτα τις πρωτογενείς πηγές:

- Termux package management: https://github.com/termux/termux-packages/wiki/Package-Management
- Python virtual environments: https://docs.python.org/3/library/venv.html
- Android APK signatures: https://source.android.com/docs/security/features/apksigning
- GitHub Actions hardening: https://docs.github.com/en/actions/how-tos/secure-your-work
- GitHub artifact provenance: https://docs.github.com/en/actions/concepts/security/artifact-attestations

Για reverse engineering χρησιμοποίησε αρχεία δικής σου κυριότητας ή αρχεία που έχεις εξουσιοδότηση να εξετάσεις. Μην εκτελείς άγνωστα binaries και μη δημοσιεύεις credentials. Ξεχώριζε πάντοτε την προβλεπόμενη συμπεριφορά από τη συμπεριφορά που πράγματι παρατηρήθηκε.

## Πώς συντηρείται ένα δίγλωσσο μάθημα

1. Άνοιξε το Markdown μέσα στο `Developer's Mind/Keep Programming Alive/Greek/` ή `English/`. Βρες το αντίστοιχο `p` path στο `DedSec-Project-Website/data/el.js` ή `en.js`. Η εγγραφή και το αρχείο πρέπει να έχουν **ταυτόσημο ουσιαστικό κείμενο**, εκτός από το τελικό newline του αρχείου.
2. Διατήρησε το ίδιο θέμα και στις δύο γλώσσες. Μετάφρασε φυσικά την εξήγηση, αλλά κράτησε τις κυριολεκτικές εντολές και λέξεις σύνταξης. Μην προσθέτεις επαναλαμβανόμενο γενικό κείμενο απλώς για να μεγαλώσει το αρχείο.
3. Εκτέλεσε από τη ρίζα `python scripts/audit_knowledge_depth.py --strict`, `python scripts/audit_near_duplicates.py`, `python scripts/audit_offline_links.py`, `python scripts/validate.py`, καθώς και `python -m unittest discover -s scripts -p 'test_*.py'`. Οι αποτυχίες πρέπει να διορθώνονται, όχι να καταργούνται οι έλεγχοι.
4. Δημιούργησε χωριστά builds για main, test, backup με `scripts/build_portable_site.py --target ... --output ...` και έλεγξε καθένα με `scripts/test_portable_site.py`. Τα sitemap, Open Graph και canonical URLs απαιτούν τον σωστό προορισμό για κάθε deployment.
5. Για δοκιμές λειτουργικού ή compiler χρησιμοποίησε πραγματικό περιβάλλον και αποθήκευσε την παρατηρούμενη έξοδο. Όπου λείπει, σημείωσε «δεν εκτελέστηκε». Ο έλεγχος σύνταξης δεν είναι πλήρης δοκιμή συμπεριφοράς.

## Τι αποδεικνύουν οι έλεγχοι

Ο strict editorial audit ελέγχει βάθος κειμένου, δίγλωσση αντιστοίχιση, κενές ενότητες και ουσιαστικές επαναλήψεις. Ο επιπλέον auditor συγκρίνει ακολουθίες τεσσάρων λέξεων και επισημαίνει πολύ όμοια κείμενα με όριο Jaccard 0,72. Ο έλεγχος static site εξετάζει links, social previews και sitemap. Αυτά δεν αποτελούν απόδειξη ότι κάθε σπάνια γλώσσα έχει ελεγχθεί σε compiler, ότι όλα τα Android/Windows σενάρια λειτουργούν στη συσκευή ή ότι η προσβασιμότητα έχει πιστοποιηθεί.

## Όρια δημοσίευσης

Το ZIP είναι **πηγαίο, φορητό πακέτο** και δεν ενημερώνει μόνο του το production. Χρησιμοποίησε την ίδια πηγή για `dedsec1121fk/dedsec1121fk.github.io`, `dedsec1121fk/Test` και `sal-scar/ded-sec`, δημιουργώντας ξεχωριστά metadata ανά προορισμό. Μην δένεις relative links στο κύριο domain. Κάθε νέα αλλαγή πρέπει να έχει μετρήσιμες αποδείξεις, ελάχιστες παρενέργειες και ακριβή ιστορικό.
